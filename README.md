# Job Matcher · 求职岗位匹配分析器

把招聘网站上的 JD 变成**三件具体的事**：这个岗位值不值得投、简历该怎么改、面试该复习什么。

不同于"自动投递"类工具，这个项目**不碰招聘平台的账号**，只处理你手动粘贴的 JD 文本。它的价值不在"投得快"，而在"投得准、改得对、准备得充分"。

```
粘贴 JD
   ├─→ 匹配度评分与风险识别        → 决定投不投、先投哪个
   ├─→ 简历要点重排 + 摘要生成      → 决定简历怎么改
   └─→ 知识点清单 + 面试问题        → 决定面试前复习什么
```

**三个核心能力**：

| 能力 | 输入 | 输出 |
|---|---|---|
| **匹配分析** | JD + 你的能力画像 | 0-100 分、S/A/B/C/D 评级、六维度得分、风险红线 |
| **简历定制** | JD + 你的简历要点（`highlights`） | 按相关度重排的要点、针对性摘要、短板建议、未覆盖关键词 |
| **复习计划** | JD + 内置知识库 | P0/P1 知识点清单、面试问题、两天安排、项目讲述骨架 |

---

## 为什么做这个

找工作真正的痛点不是"岗位不够多"，而是：

| 真实痛点 | 这个工具的答案 |
|---|---|
| 收藏了几十个岗位，不知道先投哪个 | **六维度加权评分**，直接给出 0-100 分和 S/A/B/C/D 评级 |
| 投了很多没回音，不知道为什么 | **每个人的短板和风险点都明确列出**（比如"要求 React 深度，你的主栈是 Vue"） |
| 不知道自己投递的转化率 | **投递漏斗统计**：回复率、面试率、offer 率 |
| 每次写打招呼语都要重新想 | **AI 生成个性化招呼语**（可选，支持免费模型） |
| 复盘时想不起当时为什么投它 | **Markdown 报告导出**，含完整评分依据 |

## 快速开始

**要求**：Node.js 18+（零第三方依赖，不需要 `npm install`）

### 使用流程（产品的真实起点）

```
① 注册 / 登录          → 每个账号独立数据，互不可见
② 导入你的简历         → 解析成「可被 JD 匹配的要点」，这是所有评分的基础
③ 导入 JD             → 基于你这份简历打分、排序
④ 改简历 / 备面试       → 针对该岗位重排要点、生成复习清单
```

第一步是**你的简历**，不是示例数据。没导入简历时，系统会直接把你带到「我的简历」页。

```bash
git clone <your-repo-url> job-matcher
cd job-matcher

# 直接跑
node src/server.js
```

打开 http://127.0.0.1:7788 即可。

### 想先看效果？用演示数据

不想先配画像？一行命令生成 12 个演示岗位，直接体验评分、排序和漏斗统计：

```bash
node scripts/seed-demo.js --dir data-demo

# 用演示数据启动（不影响你的真实数据）
JOB_MATCHER_DATA_DIR=data-demo node src/server.js
```

演示数据包含 4 个 S / 3 个 A / 2 个 B / 1 个 C / 2 个 D 级岗位，
以及「已投递 → 回复 → 面试 → offer」的完整状态分布。

> 所有公司名、岗位、薪资均为**虚构示例**，不来自任何招聘平台的实际抓取。
> 重新生成：加 `--force`；重置全部：删掉目录重跑。

> 正式使用请先改 `data/presets/profile.json` 成你自己的画像，见下方「配置你的画像」。

## 核心功能

### 1. 六维度匹配评分

评分基于你的能力画像与 JD 文本的关键词重合度，加权计算：

| 维度 | 默认权重 | 说明 |
|---|---|---|
| 前端架构与工程化 | 25 | 模块化、Monorepo/多仓、构建发布、性能优化 |
| AI 应用落地 | 25 | 大模型对接、RAG、Prompt、Agent、端侧推理 |
| 小程序与多端 | 15 | 微信生态、Taro、uni-app、企业微信 |
| 后端与全栈 | 15 | Node/Python 服务端、数据库、容器化部署 |
| 系统设计与性能 | 10 | 权限体系、可视化、监控、稳定性 |
| 团队管理 | 10 | 带团队、需求评审、技术选型 |

**权重和关键词全部可改**，见 `data/presets/profile.json`。

### 评分怎么算的

不是简单加权求和，分两步：

```
① 满足度 matchRatio = Σ(命中维度的得分) / Σ(命中维度的权重)
   → 只算「JD 真正要求的维度」，回答：它要的东西我有没有

② 广度 breadth = Σ(命中维度的权重) / 全部维度权重
   → 回答：这个岗位能用上我多少能力

总分 = 100 × (满足度 × 0.7 + 广度 × 0.3) + 各类修正
```

**为什么分母只算「JD 要求的维度」**：如果分母永远是你全部能力的权重和，
那么一个只要求小程序能力的岗位，即使你完美匹配，也只能拿到 15/100 分被判 D 级。
这违背了"匹配"的本意。所以分母要跟着 JD 走。

**广度的作用**：区分岗位层次。同样满足度下，要求更全面的岗位（架构+AI+管理）
比只要求单点的岗位更值得投，因为它能用上你更多能力。

评分之上还有三层修正：

- **行业加分**：命中你熟悉或目标行业（数据安全、金融、B 端等）
- **年限/层级校正**：JD 要求上限 5 年而你有 9 年，按超出年数递增扣分（每年 -3，封顶 -18），并提示 overqualified
- **减分红线**：如"外包驻场""非技术岗""React 深度要求"，直接压低总分并标注原因

### 样例库

没有现成 JD 时，「导入 JD」页顶部的样例库可以勾选后一键导入，几秒钟看到完整效果。

样例分两类，每条都标注来源：

| 类型 | 说明 |
|---|---|
| **真实** | 来自公开的官方招聘页，附来源链接（如 N-iX 的 Vue 3 / TypeScript 岗位） |
| **构造** | 按真实岗位要求的常见结构构造的示例，非真实招聘，用于覆盖不同的评分路径 |

数据在 `data/presets/jd-samples.json`，可以自己往里加。

### 导入方式

| 方式 | 适用场景 |
|---|---|
| **粘贴文本** | 单个岗位，从招聘网站选中复制 |
| **批量粘贴** | 多个岗位，用单独一行 `===` 分隔，自动去重 |
| **采集书签** | 觉得复制麻烦：拖一次书签到书签栏，以后在岗位页点一下就复制好 |

采集书签是一段纯前端 JS，**只在你主动点击时执行**，只读取当前页面已渲染的文本并写入剪贴板，
不发起网络请求、不登录账号、不批量抓取、不改动目标页面。是否使用请自行遵守对应网站的用户协议。

安装：

1. 页面「导入」标签页展开「一键采集书签」
2. 把「采集当前岗位」按钮拖到浏览器书签栏
3. 打开任意岗位页，点书签
4. 回到本页粘贴

### 2. 投递状态追踪

每个岗位有独立状态机，并记录完整的变更历史：

```
待投递 → 已投递 → 已查看 → 已回复 → 约面试 → 拿 offer
                                            ↘ 被拒 / 放弃
```

自动统计回复率、面试率、offer 率，用于判断自己的投递策略是否有效。

### 3. 深度复习文档

不只是知识点清单 —— 按 **9 段固定结构**生成一份可直接用来准备的文档：

```
0. 文档地图与复习优先级   ← 复习优先级表 + 项目-技术映射表
1. 面试目标画像           ← 优势 / 匹配 / 主线 / 30秒自我介绍
2. 核心技术主题复习       ← 每主题 6 个子结构
3. 项目深挖题库
4. 岗位专项准备           ← JD 关键词拆解表
5. 行为面试与负责人表达   ← 5 类 STAR 案例
6. 7/14/28 天复习计划
7. 面试前最后检查清单
```

每个技术主题有 6 个子结构，这是它和「复习提纲」的区别：

| 子结构 | 作用 |
|---|---|
| 核心概念 | 4-8 条，每条含「讲清什么 / 为什么问 / 容易踩的坑」 |
| 面试高频问题 | 每个问题 4 点答案（原理 / 取舍 / 结合项目 / 常见坑） |
| 在你的项目中 | 映射到你简历里的真实经历，含 STAR 讲法 |
| 面试官可能追问 | 3-5 个资深追问，带简洁回答 |
| 关键代码或伪代码 | 服务于面试讲解的短代码 |
| 知识图谱 | 前置知识 / 相关技术 / 进阶方向 |

### 两条生成路径

| 条件 | 走哪条 | 效果 |
|---|---|---|
| **没配模型** | 内置知识库按同一结构生成 | 约 **26,000 字**，覆盖全部 9 段与 6 子结构 |
| **配了模型** | 用移植自原项目的 Prompt 生成 | 针对你的简历定制，含续写机制防截断 |

**没配模型也能用**，这是刻意的：模型只是把「通用内容」变成「你的内容」，不该成为能不能用的开关。

AI 路径的续写机制：单轮上限 4096 token，靠 `[REVIEW_DOC_DONE]` 完成标记判断是否被截断，
未完成就带着「已生成内容结尾」续写，最多 3 轮。

### 4. AI 增强（可选）

配置模型后可以：

- 生成**针对该岗位**的打招呼语（不是群发模板）
- 给出三条投递建议：突出什么 / 准备什么 / 风险在哪

**不配置也能用**，只是少了这两项。支持免费模型，见 [docs/FREE-MODELS.md](docs/FREE-MODELS.md)。

### 4. 报告导出

Markdown（可读、可存档）或 CSV（可导入表格）两种格式，含数据概览、岗位排序、维度得分、风险提示。

## 配置你的画像

编辑 `data/presets/profile.json`，这是整个评分的基准。结构如下：

```jsonc
{
  "profile": {
    "name": "你的名字",
    "headline": "前端负责人 / 高级前端工程师（Vue 技术栈）",
    "years": 9,
    "currentCity": "北京"
  },
  "dimensions": [
    {
      "id": "frontend_arch",
      "name": "前端架构与工程化",
      "weight": 25,              // 权重，总和不必等于 100
      "level": 5,                // 1-5，你的熟练度
      "description": "一句话说明",
      "keywords": {
        "架构": 3,               // 关键词: 权重（1-5）
        "Monorepo": 4,
        "Vue": 4
      }
    }
  ],
  "domains": [
    { "name": "金融", "keywords": ["银行", "保险"], "bonus": 4 }
  ],
  "negatives": [
    { "keywords": ["外包", "驻场"], "penalty": -15, "reason": "外包岗位" }
  ],
  "resumeText": "你的简历正文，AI 生成打招呼语时会用到"
}
```

### 简历要点（highlights）

简历定制功能依赖这个字段。每条要点包含：要点文本、所属维度、用于匹配的关键词。

```jsonc
"highlights": [
  {
    "id": "h01",
    "dims": ["frontend_arch"],
    "keywords": ["架构", "模块化", "Monorepo", "解耦"],
    "text": "主导中后台系统前端架构解耦，拆分为主应用 + 6 个独立发版模块包"
  }
]
```

生成建议时，工具会把每条要点的 `keywords` 与 JD 比对，结合所属维度在本岗位的强度，
排出「建议前置 / 可保留 / 建议弱化」三档，并用高分要点拼出一段针对性摘要。

**写要点时注意**：一条要点只讲一件事，`keywords` 填这条经历真实涉及的技术点，
`text` 里带上可验证的结果（数字、范围、效果）。

### 评级阈值

默认 S≥88 / A≥75 / B≥58 / C≥40，可在 profile.json 覆盖：

```jsonc
"grades": { "S": 88, "A": 75, "B": 58, "C": 40 }
```

如果你的画像关键词较少、整体分数偏低，可以下调这些阈值，让评级分布恢复合理。

**调参建议**：

1. 先按你的真实技术栈改 `dimensions` 的 `keywords`
2. 用 5-10 个你熟悉的真实 JD 试跑，看排序是否符合直觉
3. 排序反直觉时，优先调 `weight`，再调关键词权重
4. 改完回页面点「重新评分」，会自动备份旧数据

## 数据与隐私

| 项目 | 说明 |
|---|---|
| 账号 | 邮箱 + 密码，密码用 scrypt 加盐哈希，会话是签名 Cookie |
| 数据隔离 | 每个用户独立目录 `data/users/<id>/`，互相看不到 |
| 数据存放 | 全部在服务器本地，纯 JSON 文件 |
| 上传行为 | **不上传任何数据到第三方服务器** |
| 招聘平台账号 | **不接触**，不做登录、爬取、自动投递 |
| API Key | **只从环境变量读取**，不写数据库、不写文件、不返回给浏览器 |
| AI 调用 | 只在主动点「生成打招呼语」时发生，会把该岗位 JD 发给模型提供方 |

详细安全设计见 [SECURITY.md](SECURITY.md)。

## 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `JOB_MATCHER_PORT` | `7788` | 监听端口 |
| `JOB_MATCHER_HOST` | `127.0.0.1` | 监听地址，公网部署建议保持默认并用 Nginx 反代 |
| `JOB_MATCHER_TOKEN` | 空 | 访问口令。**公网部署必须设置** |
| `JOB_MATCHER_PROVIDER` | 自动探测 | 指定 AI 供应商：`openrouter` / `nvidia` / `deepseek` / `openai` / `qwen` / `moonshot` / `ollama` |
| `JOB_MATCHER_MODEL` | 供应商默认 | 覆盖模型名 |
| `JOB_MATCHER_BASE_URL` | 供应商默认 | 覆盖接口地址 |
| `JOB_MATCHER_AI_KEY` | 空 | 通用 Key（不指定 provider 时使用） |
| `JOB_MATCHER_AI_DAILY_LIMIT` | `200` | AI 每日调用上限 |
| `JOB_MATCHER_RATE_LIMIT` | `120` | 每 IP 每分钟请求上限 |
| `JOB_MATCHER_DATA_DIR` | `<项目根>/data` | 数据目录，用于跑多个实例（如真实 + demo） |
| `JOB_MATCHER_TIMEOUT_MS` | `60000` | AI 请求超时 |

示例：

```bash
# 用 OpenRouter 的免费模型
JOB_MATCHER_PROVIDER=openrouter \
OPENROUTER_API_KEY=sk-or-v1-xxx \
JOB_MATCHER_TOKEN=$(openssl rand -hex 16) \
node src/server.js
```

## 为什么不用数据库

这是刻意的设计：

1. **单人使用场景**，数据量在几百条量级
2. **零依赖**，clone 下来就能跑，不需要装 MySQL/Postgres
3. **数据可读可改**，出问题可以直接看 JSON
4. **便于备份和版本管理**

数据层集中在 `src/store.js`，要换成 SQLite 或 Postgres 只需替换这个文件。

写入使用「临时文件 + 原子 rename」，避免进程中断写坏数据。

## 已知边界

诚实说明，避免误解：

- **评分是关键词启发式的**，不理解语义。同义改写会漏判（如"前端基建"与"前端基础设施"）。它做的是**相对排序**，不是绝对判定。
- **不是投递工具**。投递动作仍然要你手动完成，这是刻意设计（见下节）。
- **不判断公司好坏**。只看 JD 文本匹配度，不知道公司是否靠谱、是否加班。
- **AI 建议仅供参考**。模型会犯错，不要盲信它说"这个岗位很适合你"。
- **单用户设计**。没有多租户隔离，不适合多人共用一套部署。

## 为什么不自动投递

这是本项目最重要的设计决策。

技术上，用 Puppeteer 模拟登录 BOSS 直聘批量投递是可以做到的。但：

1. **违反平台用户协议**，账号绑定实名，风险不可逆
2. **平台有风控**，异常投递行为会导致账号受限
3. **每日沟通额度有限**，自动化会把额度烧在不匹配的岗位上，反而降低回复率
4. **群发消息一眼可见**，你的招呼语立刻失去说服力

**结论**：把力气花在"筛选和策略"上，比"投递速度"回报高得多。这个工具做的是前者。
