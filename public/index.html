核心能力

三个问题，三个答案

求职真正耗神的不是「投得多不多」，而是这三个判断。

01

这个岗位值得投吗

六维度加权评分，把「感觉还行」变成可比较的分数字，并明确指出风险点。

  • 技能重合度、行业匹配、年限层级
  • 外包 / 年限偏低 / 方向不符等红线识别
  • S/A/B/C/D 五档排序，先投哪个一目了然
02

简历该怎么改

针对这一份 JD，把简历里该前置的经历挑出来，把该补的短板指出来。

  • 按相关度重排你的简历要点
  • 生成一段针对该岗位的简历摘要
  • 列出 JD 提到但你没覆盖到的关键词
03

面试该复习什么

从 JD 里反推知识点清单，按优先级排出复习顺序和可能被问的问题。

  • JD 关键词精确映射到知识点
  • P0/P1 优先级 + 两天复习安排
  • 项目讲述的 STAR 骨架提示
使用流程

三步，一次完整的投递准备

STEP 1

粘贴岗位描述

从招聘网站复制 JD 粘贴进来。支持批量，自动识别公司与职位并去重。

STEP 2

看匹配度、改简历

拿到分数和风险提示，按建议调整简历要点顺序，生成针对性摘要。

STEP 3

按清单复习，投出去

照着 P0 清单准备，用 STAR 结构把项目讲清。投完推进状态，复盘转化率。

常见问题

你可能想知道的

会抓取招聘网站的数据吗？
不会。工具只处理你自己粘贴进来的文本，不登录任何招聘平台、不发起爬取请求。 招聘平台的用户协议普遍禁止自动化采集，账号又绑定实名，一旦被判定爬虫，代价远大于省下的时间。 如果觉得复制麻烦，可以用页面里提供的采集书签：你手动打开岗位页、手动点一下，它把当前页面内容复制到剪贴板。
评分是怎么算的？准吗？
基于关键词与权重计算，不是语义模型。它会按「JD 实际要求的维度」算满足度，再叠加广度和各类修正项。 优点是可控、可解释、零成本；缺点是同义改写会漏判（比如 JD 写「前端基建」而词表里是「基础设施」）。 所以它的价值是相对排序，不是绝对判定。词表和权重都可以自己改。
数据存在哪里？安全吗？
全部存在服务端本地文件里，不上传到任何第三方。模型 API Key 只从环境变量读取， 不写数据库、不写文件、不返回给浏览器。AI 功能默认关闭，没配 Key 时评分、简历建议、复习计划照常可用。
为什么不做自动投递？
技术上能做到，但收益被高估了。平台每日沟通额度有限，自动投递会把额度烧在不匹配的岗位上， 反而拉低回复率；群发招呼语一眼就能看出来。把力气花在「筛得准、改得好、准备充分」上，回报更高。
可以用自己的简历吗？
可以，而且必须。评分的基准是 data/presets/profile.json 里的能力画像与简历要点， 简历定制功能依赖其中的 highlights 字段。改成你自己的内容后，评分和建议才有意义。

推荐岗位

按你的画像和每个岗位的匹配度自动分组。每组下面是「为什么推荐你」的理由和可能的风险， 点进详情可以直接看简历怎么改、面试该复习什么。

导入岗位描述

从 BOSS 直聘、智联招聘、猎聘或公司官网复制 JD 文本粘贴到这里。 批量导入时用单独一行 === 或 --- 分隔。系统按「公司 + 职位」自动去重。

觉得复制粘贴麻烦？用一键采集书签 拖一次，以后在岗位页点一下就复制好

把下面这个链接拖到浏览器书签栏。以后在招聘网站打开任意岗位页， 点一下书签，它就会把当前页面内容复制到剪贴板，你回来粘贴即可。

采集当前岗位

说明：书签只在你主动点击时执行，只读取你当前看到的页面文本并写入剪贴板， 不发起任何网络请求、不登录账号、不批量抓取。是否使用请自行遵守对应网站的用户协议。

怎么安装书签？
  1. 显示书签栏：Chrome / Edge 按 ⌘⇧B（Mac）或 Ctrl+Shift+B（Win）
  2. 把上面的「采集当前岗位」按钮拖到书签栏
  3. 打开任意岗位页面，点这个书签
  4. 回到本页，⌘V / Ctrl+V 粘贴到上面的输入框
